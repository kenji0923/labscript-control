labscript-control operations guide

A shared CLI and MCP interface for Windows BLACS and Runmanager. Remote clients use SSH; native Windows clients can connect directly to the same authenticated localhost API.

Installation

Install this package into the Python environment that runs BLACS and Runmanager. Keep the existing experiment profile separate from this repository.

git clone https://github.com/kenji0923/labscript-control.git

# PowerShell on the control PC:
$daqPython = 'C:\path\to\labscript-env\Scripts\python.exe'
& $daqPython -m pip install C:\src\labscript-control
& $daqPython -m labcontrol.install_windows `
  --labscript-root C:\path\to\labscript-suite

The profile root must contain labconfig\COMPUTERNAME.ini. Use --labconfig to provide another machine-specific INI. Run the installer as the same Windows user that runs the applications. The installer locates the installed application modules without importing their GUI/hardware dependencies, validates its edits, writes backups, and registers tasks. It does not start applications or run shots.

For local MCP, create a separate Python environment and install the MCP extra there. Then provide that environment to the bridge installer:

python -m venv C:\path\to\agent-env
& C:\path\to\agent-env\Scripts\python.exe -m pip install 'C:\src\labscript-control[mcp]'
& $daqPython -m labcontrol.install_windows `
  --labscript-root C:\path\to\labscript-suite `
  --mcp-python C:\path\to\agent-env\Scripts\python.exe

The generated mcp-client.json and mcp-codex.toml files in %LOCALAPPDATA%\LabscriptAgentControl are configuration examples. Register the appropriate example with your agent. Each configured Python environment must have this package installed. After installing the bridges, normally close and reopen both applications to load them.

Application startup uses tasks LabscriptAgent-BLACS and LabscriptAgent-Runmanager, running with the logged-on user's interactive token and normal privileges. The user must remain logged on; an SSH login alone does not create that desktop session. WSL clients should invoke Windows Python or use SSH rather than assuming WSL localhost is the Windows control endpoint.

Target configuration

Copy examples/targets.example.json to a private configuration file. Set each target's actual Windows hostname, SSH host alias, and Python executable. That Python executable must be able to run python -m labcontrol. There is no requirement for the package checkout to live inside the experiment repository.

OptionBehavior
--localConnect directly to this machine; no SSH required.
--target lab-aLoad a profile; use local transport if its hostname matches this machine, otherwise SSH.
--transport sshForce SSH for a named target.
--transport localForce local transport, refusing a mismatched target hostname.
No target optionNative Windows defaults to local. Other platforms use default_target from the configuration file.

--host is an alias for --target. Configuration lookup uses --config, then LABCONTROL_CONFIG, then %LOCALAPPDATA%\LabscriptAgentControl\targets.json on Windows or $XDG_CONFIG_HOME/labscript-control/targets.json elsewhere (default ~/.config/labscript-control/targets.json).

labctl --config targets.json --target lab-a status
labctl --config targets.json --target lab-b status host
labctl --local status

status host works while the applications are stopped. Responses identify the actual hostname. Named-target requests are checked on the execution host before mutations. SSH uses --ssh-config if specified, otherwise an existing ~/.ssh/config, otherwise OpenSSH defaults. For an MCP process using an SSH authentication agent, pass SSH_AUTH_SOCK into its environment or configure IdentityAgent in SSH settings. Never copy credentials into the target JSON.

Leases for multiple agents

A lease reserves both applications on one PC across commands and normal application restarts. Local CLI, remote CLI, and MCP all share the lease. Reads remain available. Mutations without the matching lease ID are rejected while a lease is active.

labctl --local lease acquire --owner agent-a --ttl 300
# Save result.lease_id from the response:
labctl --local --lease-id UUID queue pause
labctl --local --lease-id UUID --wait tab restart camera
labctl --local --lease-id UUID lease renew --ttl 300
labctl --local --lease-id UUID lease release
labctl --local lease status

TTL is 30–3600 seconds; the default is 300. Renew before expiration. An expired or released lease ID cannot authorize another mutation. Each acquire, renew, and release needs a new request ID; resending an old request returns its receipt without extending the lease. The owner label is descriptive; use a UUID as the lease credential. Status responses do not disclose that credential.

Individual mutations are permitted when no lease exists, and their synchronous execution is serialized across clients. A lease is needed to coordinate a multi-step operation, including waiting for asynchronous startup. Leases are cooperative: GUI buttons and other native labscript APIs do not use this lock. Lease expiration or release does not abort a running shot.

Queue and application commands

CommandBehavior
queue listRead paths, revision, pause/repeat, and current state.
queue pausePrevent the next shot from starting. A running shot continues.
queue resumeCheck device readiness and resume. Pending shots can operate hardware.
queue abortUse BLACS's normal Abort action, and pause.
queue add --path 'Z:\...\shot.h5'Require a paused queue and a fresh, unrun shot. BLACS checks its connection table.
queue remove --index 0 --revision REVRemove one pending shot while paused. Indexes start at zero.
queue move --index 0 --destination 2 --revision REVMove to the specified final index while paused.
queue clear --revision REVClear pending shots while paused.
queue repeat --enabled falseEnable/disable the existing repeat mode.
tab restart NAMERestart one device tab while BLACS is idle.
app start|stop|restart blacs|runmanagerStart an application, or request normal shutdown/restart.

Use the revision returned by the latest queue list. Editing is rejected if another client or the GUI changed the queue. H5 access occurs in the application's desktop session, allowing mapped drives that are unavailable to an SSH shell.

Restarts are refused during a shot and leave BLACS paused. --wait waits for a new application PID or worker PIDs and readiness after start/restart (default 120 seconds; change with --timeout). It does not wait for stop. Use --broken-tabs preserve to retain failed-tab settings when shutting down BLACS. No automatic forced termination is provided.

Runmanager

labctl --local runmanager globals
labctl --local runmanager set-globals --values '{"hold_time": "1.0"}'
labctl --local runmanager select --path 'C:\experiments\shot.py'
labctl --local runmanager compile
labctl --local runmanager abort

Globals are Python-expression strings from active groups. An empty selection returns an empty mapping. Compile initiates compilation without submitting shots to BLACS or Runviewer, and preserves the GUI's Run shot(s) setting. accepted means the request was accepted, not that compilation succeeded. Read compilation state through status and inspect Runmanager Output for detailed errors.

A Runmanager restart saves current GUI state to the autoload configuration and backs up the previous file with a .before-agent-restart suffix. BLACS uses its normal front-panel save and worker shutdown path.

Mutation receipts

labctl --local --request-id restart-001 --wait app restart runmanager
labctl --local operation runmanager restart-001
labctl --local operation host lease-request-id

CLI commands generate request IDs when omitted; MCP mutations require them explicitly. Receipts are durable across process restarts and include app start and lease operations. An identical request ID and payload returns the existing receipt instead of repeating the action. Reusing an ID for different parameters is rejected. Query receipts and current state after uncertain transport failures; outcome_unknown means the outcome cannot be confirmed. Receipts can be read while applications are stopped.

MCP tools

Start labcontrol-mcp --local or labcontrol-mcp --config targets.json --target lab-a. Module execution is also supported: python -m labcontrol.mcp_server. Register distinct server names for distinct targets.

The 16 tools are labscript_status, labscript_application, labscript_operation, labscript_lease_status, labscript_lease, blacs_queue_list/control/add/edit/repeat, blacs_restart_tab, and runmanager_globals/set_globals/select_script/compile/abort_compile. Mutation tools accept lease_id. Use a tool timeout of at least 180 seconds for restart waits.

Updates and migration

From the original script-based deployment, install this package in the experiment Python environment and run the installer with the existing labscript profile root. The installer recognizes the existing hook markers and replaces the old checkout-path hook with the installed package import. Existing token, lease database, and receipts remain in the same control-state directory. Normal application restarts activate the new code. Remote profiles now identify a Python with this package installed; an experiment-repository root is no longer part of the SSH transport configuration.

The standalone distribution's installer has source-edit and packaging tests. Exercise updates on an idle apparatus. Keep the experiment's configuration and running installation until the new bridge is confirmed. Application package upgrades may replace the BLACS plugin or Runmanager hook, requiring reinstallation.

Backup manifests in %LOCALAPPDATA%\LabscriptAgentControl\backups record paths and before/after hashes. To roll back, normally stop the apps and restore only matching files; do not overwrite unrelated later edits. The installer never copies an existing control PC's token or experiment data into this repository.

Transport and scope

BLACS listens on 127.0.0.1:47140 and Runmanager on 127.0.0.1:47141, authenticated by a per-user bearer token. There is no need to expose these HTTP ports to the LAN. Use the same Windows account as the applications for local or SSH access. This project is a control integration, not a substitute for apparatus interlocks or labscript's shot timing.

Protocol and controller tests do not connect to laboratory hardware or run shots. See the repository's GitHub Actions results for the tested Python/OS matrix. Released under the MIT License.
